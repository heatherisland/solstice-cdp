# Solstice CDP

A composable CDP built end to end — Snowflake, dbt and Hightouch — for a fictional
direct-to-consumer skincare brand. Every customer, order and event in it is synthetic,
generated by the SQL in `sql/`. No real company or customer data is involved anywhere.

**[Open the walkthrough →](https://heatherisland.github.io/solstice-cdp/)**

---

## The problem

Solstice Skin sells a 40-SKU skincare line through Shopify, an iOS app and a small
wholesale channel. Roughly 5,000 customers, 14,000 orders, 900 replenishment
subscriptions. Every segment they can build lives inside their ESP, so it only sees
email behavior and the orders an app syncs across — subscription state, wholesale
orders and web browsing are invisible to marketing. A list request takes a week.
Paid media still serves ads to people who ordered on Tuesday.

They have a Snowflake instance a contractor stood up and nobody uses, no data team,
and no budget for an enterprise CDP. Which is the exact situation composable is for.

## What this builds

| Layer | What's here |
| --- | --- |
| Warehouse | `sql/` — environment setup, synthetic seed data, verification |
| Transformation | `dbt/` — identity spine, anonymous resolution, customer_360, ad identifiers |
| Activation | `hightouch/` — workspace export, sync telemetry |
| Destination | `lambda/` — a Braze-contract endpoint that validates rather than accepts |
| Infrastructure | `terraform/` — the activation layer as code |
| Operations | `docs/RUNBOOK.md` — five failure modes and what to check |

## The decisions worth arguing about

Three choices in here required judgment rather than syntax. They're written up in
[`docs/decisions.md`](docs/decisions.md):

1. Which record survives an identity merge, and what happens to consent
2. Why churn risk is measured against each customer's own cadence, not a fixed window
3. Why discount-dependent customers are excluded from the discount branch

## Running it yourself

You need a Snowflake account (the trial is enough), a Hightouch workspace, and
optionally an AWS account for the webhook destination. Start with `sql/00_keys.sh`
and work forward — the walkthrough has the full sequence with the reasoning attached.

Nothing here contains credentials. `*.p8`, `.env` and `profiles.yml` are gitignored;
`dbt/profiles.example.yml` shows the shape without the secrets.
